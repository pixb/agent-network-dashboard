### 1.1 R2 复核结论：TopoGraph 的 `rounded-md` **不迁移**

R2 范围（`app/components/TopoGraph.tsx`）复核时发现源码里有**既有的两级层次决定**
（R375/R376 注释原文）：

```
segmented control container = rounded-lg (8px)
standalone button           = rounded-md (6px)   ← 刻意保留
```

该文件 21 处「命中」中：**13 处是真实类名**、3 处仅注释提及、5 处是历史迁移说明。
13 处真实用法全部是 standalone chip / 图标按钮（`px-2.5 py-1`、`p-1.5`），属于上述档位。

**结论：R2 不迁移**。机械统一到 8px 会把「容器 / 独立按钮」两级层次抹平——
按批准的原则「不为统一而统一」，这一批改为**记录理由并关闭**，不再占用迁移批次。
若将来设计系统明确取消两级层次，再统一处理。

`DESIGN.md` 只有「暗色主题适配 / 变更与验证」等 3 节，没有 typography 或 radius 表；
也找不到 `tokens.json`。清单里的 `11/12/14/16/20` 与 `2/4/6/8/…` 来自**客户端设计系统**（任务卡引用），
在本仓不可核验。

后果：R1/R3 的迁移依据是任务卡陈述的刻度，而不是本仓可查的文档。这本身不算错，
但**字号批（F1–F5）在拿到刻度原文前不应开工**——否则又是一次「凭任务卡数字改 208 处」。

## 4. 不可自动化判断的部分（明确边界）

- `rounded-md` 在某些「输入框内联按钮」上可能是刻意的小圆角，机械替换会改变控件辨识度；
- `text-[9px]` 在状态点/角标里承担「极小徽标」语义，直接放大可能撑破卡片；
- 因此每一批都必须**截图比对**，不接受「数量归零」作为完成标准。
